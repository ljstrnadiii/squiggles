# Project rules

- Canonical activity data is Parquet/GeoParquet.
- DuckDB SQL is the query language; do not add a query DSL.
- Keep canonical data, query execution, rendering, and control-plane metadata separate.
- Prefer Arrow/GeoArrow; avoid GeoJSON for large intermediate data.
- Browser and hosted execution must preserve SQL semantics.
- Treat activity locations as private; authorize before data access.
- Hosted SQL is read-only and limited to approved relations.
- Ingestion uses adapters so source formats remain replaceable.
- The current source adapter supports Strava exports; design for other activity archives.
- Local and cloud ingestion share the same compiler.
- Do not upload raw export archives to hosted storage; compile locally first where possible.
- Tests use synthetic data only.
- Pulumi owns persistent AWS infrastructure.
- Prefer serverless/scale-to-zero AWS services.
- No NAT Gateway, RDS/Aurora, EKS, OpenSearch, ElastiCache, or always-on compute without an explicit decision.
- Keep development infrastructure under $50/month.
- Measure performance changes before and after when practical.
- Do not assume MVT beats direct Arrow rendering; benchmark through `RenderPlan`.
- MCP/AI are normal API clients with no privileged data access.
- Work in small stages; update tests and docs with behavior changes.
